# ⚠️ Known Limitations, Platform Quirks & Community Solutions

> **Language / Bahasa**: [**English**](KNOWN-LIMITATIONS.md) | [**Bahasa Indonesia**](id/KNOWN-LIMITATIONS.id.md)

This document outlines known technical constraints, Windows platform-specific behaviors, and practical workarounds in **WinTokenMon (`v0.1.0-beta`)**.

---

## 📋 Summary of Known Limitations

| Area | Limitation | Technical Cause | Recommended Workaround |
| :--- | :--- | :--- | :--- |
| **🪟 Transparency** | Faint edge pixels on certain dark themes | Windows Tkinter uses binary colorkey transparency (`-transparentcolor`) rather than per-pixel 8-bit alpha channels. | We enforce crisp `NEAREST` pixel scaling. Setting a slightly brighter desktop wallpaper or adjusting opacity in Settings mitigates haloing. |
| **🖥️ Multi-Monitor** | Potential scaling jump on mixed DPI monitors | Tkinter processes inherit the primary display's DPI scaling factor (e.g. 150% 4K primary vs 100% 1080p secondary). | Window clamping keeps the pet safely within monitor bounds. Setting consistent Windows DPI scaling across monitors provides optimal results. |
| **🎮 Fullscreen Apps** | Pet hidden during exclusive 3D games | DirectX / Vulkan "Exclusive Fullscreen" takes over the primary GPU swapchain, bypassing desktop window managers. | Run games or full-screen apps in **"Borderless Windowed"** mode if you wish to keep your Pokémon companion visible. |
| **⏱️ Ingestion Latency** | 0–10 second delay in token count updates | Polling runs on a 10-second sweep cycle with $O(1)$ file stat caching to ensure **0% background CPU usage**. | Normal by design. Tokens will update immediately on the next 10-second sweep cycle after your IDE flushes logs to disk. |
| **🌐 Offline Mode** | First-time encounters display fallback egg | Pokémon GIF sprites and `.ogg` cries are resolved on-demand from PokéAPI / Showdown CDN to comply with zero bundled ROM assets. | Previously hatched companions are cached forever locally in `%APPDATA%\WinTokenMon\`. Un-cached species fallback gracefully to an Egg sprite & synthesized 8-bit chiptunes without crashing. |
| **🎨 Sprite Variety** | Sprites use battle stance idle loops | Public PokéAPI/Showdown endpoints only host Gen-V battle stance GIFs (no dedicated walk/run/sleep sprite sheets). | Programmatic walking gait physics (vertical step-hops, cadence acceleration, waddle sway, and dust puffs) simulate real walking dynamics. |
| **📌 Taskbar Snap** | Slight overlap with Auto-Hide Taskbar | Snapping to taskbar uses standard Windows taskbar height constants (48px). | If using Windows "Auto-Hide Taskbar", simply drag the pet a few pixels higher on the screen. |

## 🔍 Deep-Dive Explanations

### 1. Showdown Battle Sprite Constraints vs. Procedural Walking Physics
The community PokéAPI and Pokémon Showdown repositories exclusively host front/back **battle idle animation loops** from the Generation V Nintendo DS games. There are no official walking, running, sleeping, or eating sprite sheets distributed by these APIs.
- **How WinTokenMon Simulates True Movement**: Rather than sliding static battle animations, our custom animation engine proceduralizes movement:
  1. Accelerating GIF frame playback from $100\text{ms}$ (resting) to $50\text{ms}$ (walking) to make limbs cycle faster.
  2. Applying a harmonic step-hop bounce curve ($Y = -|6 \cdot \sin(t)|$) and lateral weight sway ($X = 2.5 \cdot \sin(t)$).
  3. Emitting footstep dust particles (`💨`) and performing turnaround hops when changing direction.

---

### 2. Colorkey Transparency vs. True Per-Pixel Alpha
On Windows, standard Tkinter top-level windows achieve transparency using a colorkey mask (`wm_attributes("-transparentcolor", colorkey)`). Any pixel matching the designated color (e.g. `#000001`) becomes 100% pass-through.
- **Why this matters**: True semi-transparent antialiasing (e.g., 50% opacity shadow pixels) is blended against the colorkey before Windows clips it, which can produce subtle 1px border fringes.
- **Our Solution**: We preprocess animated Showdown GIF frames using Pillow with strict nearest-neighbor quantization (`Image.Resampling.NEAREST`), preserving the sharp retro pixel-art aesthetic of Generation V Pokémon without blurry alpha artifacts.

---

### 2. Multi-Provider Log Flush Behavior
WinTokenMon reads real token logs generated by external developer tools:
- **Cursor IDE**: Writes conversation bubbles to `%APPDATA%\Cursor\User\globalStorage\state.vscdb` (SQLite WAL mode).
- **Claude Code**: Appends JSONL entries to `~/.claude/projects/**/*.jsonl` upon completing an assistant turn.
- **Antigravity CLI**: Writes binary Protobuf metadata into `~/.gemini/antigravity-cli/conversations/*.db`.

Because these tools flush to disk upon turn completion (rather than per-character streaming), token counters and EXP bars update in discrete bursts as you code.

---

### 3. Offline Resilience & Asset Fallback
In accordance with our [Legal Disclaimer](../DISCLAIMER.md) (`NFR-01`), no copyrighted sprites or audio files are bundled inside the repository.

When working in an offline environment (e.g., traveling without internet):
1. **Sprites**: Any Pokémon you have previously encountered is already cached in `%APPDATA%\WinTokenMon\sprites\`. If a new species hatches while offline, it temporarily renders as an animated incubating Egg until an internet connection is available to download the Showdown GIF.
2. **Audio Cries**: Cry audio is fetched from PokéAPI. When offline, our in-memory **8-bit Chiptune Synthesizer** automatically takes over, synthesizing retro level-up arpeggios on the fly with zero external dependencies.
